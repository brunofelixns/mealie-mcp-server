# P22: Streamable HTTP autenticado

Fecha: 2026-10-28. /mcp usa el mismo catálogo y factory que stdio, con un solo lifespan y pool Mealie por proceso. Se prueban sockets TCP reales con el cliente oficial y FastMCP en auto (2026-07-28) y legacy (2025-11-25), catálogo78, prompt y una llamada de negocio. Dos clientes de eras distintas comparten exactamente una entrada/salida de la factory.

El Bearer personal se valida mediante la extensión pública TokenVerifier, comparando hashes SHA-256 con hmac.compare_digest. No se añaden rutas OAuth. Token ausente, incorrecto o igual a la credencial saliente no autoriza HTTP. El FakeMealie observa únicamente Bearer fixture-mealie-key; nunca recibe el token del cliente MCP. La configuración exige secretos distintos antes de arrancar; MCP_REQUIRE_HTTPS obliga a declarar una URL pública HTTPS.

FastMCP valida Host/Origin en modo explícito: host desconocido421, origen ajeno403; hostname público y origen permitido pasan. Uvicorn no confía en cabeceras forwarded ni imprime access logs. /healthz y /readyz no requieren token, devuelven estado mínimo y no llaman a Mealie. Readiness sigue la entrada/salida del lifespan. No existe /sse. JSON malformado devuelve400.

Se verifica una imagen de exactamente10MiB por multipart y una respuesta SSE con2Mi caracteres no ASCII en ambas eras. El cliente oficial se configura con max_sse_event_size32MiB. Las peticiones declaradas mayores de32MiB y las fragmentadas que exceden ese valor devuelven413. Esto detectó el límite4MiB interno del SDK, además del límite exterior inicial: se retiró la doble capa y se configuró el limitador nativo por instancia, después de entrar su lifespan y antes de readiness. FastMCP4.1.4 no expone ese argumento; el adaptador comprueba las clases de la ruta autenticada y los atributos públicos del manager/limitador. No accede a _mcp_server ni modifica globals. Esta integración requiere revisión con futuras versiones y falla al arrancar si cambia su estructura.

Una desconexión TCP durante el primer PATCH se prueba para ingredientes e instrucciones: se completa exactamente la secuencia original de verificación y rollback, con dos PATCH y sin replay. El límite MCP utiliza un socket real; las respuestas Mealie se simulan con MockTransport para controlar la pausa exacta y comprobar método/path/body. No equivale a una caída de un Mealie público. Las pruebas P16/P17 verifican también cancelación antes de escribir, durante verificación y agotamiento del cleanup.

La CLI HTTP arranca como subprocess real con logs DEBUG seguros, readiness y SIGTERM. El cliente se cierra; stdout queda vacío y los dos secretos no aparecen en stderr. Uvicorn reemite SIGTERM tras limpiar y el subprocess sale -15 (143 en Docker), comportamiento documentado. stdio mantiene salida0 al transformar señales en EOF.
