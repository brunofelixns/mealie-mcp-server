# P19: valoraciones y fechas con zona explícita

Fecha: 2026-10-28. Se portan set_recipe_rating y mark_recipe_last_made, las dos últimas herramientas de negocio. **12 casos MCP del original** comprueban rating y favorito false, mínimo/máximo de la escala, null que se envía como cero para borrar, solo favorito sin modificar rating, ausencia de campos, usuario sin id, fecha plana, offset explícito y timestamps inválidos. Esta familia se captura con un proceso original nuevo por caso: el original tiene una caché de identidad global al proceso; cada comparación Python construye su propio servidor/cliente. No se finge una consulta adicional de identidad en un proceso original que ya la tenga resuelta.

La identidad se cachea mediante un Task confinado al MealieClient de su configuración. Los fallos de GET self o un id ausente no se cachean. Cancelar un consumidor no cancela la lectura compartida de identidad; cerrar el cliente sí termina una lectura pendiente y elimina su caché. Se verifican dos clientes con credenciales distintas y reutilización del primero, sin mezclar usuarios. El escritor conserva omisión, null y false; se releen la receta y el resumen de valoración del usuario después de escribir. El resumen conserva campos extra y rating almacenado cero se devuelve como null, manteniendo el agregado tal como lo devuelva Mealie.

**62 ejemplos de fechas producidos por la función original**, con reloj fijo y TZ UTC/Europe/Madrid, se conservan en last-made-reference.json. Incluyen mediodía local, hoy antes de mediodía acotado a ahora, omisión, futuro, offsets, hueco y solapamiento de DST de Madrid, precisión de milisegundos, entrada inválida, rollover de fecha/hora ISO que Date acepta y años antiguos. La aritmética gregoriana entera permite conservar el año cero y su cruce al año negativo sin introducir Node en el runtime Python. Una fecha plana imposible se rechaza; no se cambia esa regla por la normalización distinta que Date aplica al datetime ISO. Fold=0 conserva la resolución compatible de Date ante huecos/solapamientos locales. La salida conserva el instante y el formato UTC de tres decimales.

La zona se toma de TZ validado, sin cambiar el TZ global del proceso ni depender del del host. El reloj se inyecta en la función pura; el handler usa ahora UTC. Timestamp null sigue rechazado por el esquema público original, mientras que omisión usa ahora. Rating conserva 0.5..5 en pasos de 0.5 y el booleano no se acepta como número.

El capturador usa un pequeño harness .mjs dentro de contenedores de referencia efímeros, importando sin modificar /reference/dist/lib/last-made.js. Se copian solo harness e inputs sintéticos; se verifica código de salida y número de casos antes de guardar, y se eliminan esos contenedores. Las primeras pruebas con node -e desde el Docker anidado devolvieron salida vacía incluso con código de salida cero para ciertos argumentos; no se infiere una causa del fallo ni se usa esa salida como evidencia. Los fallos de colección mientras faltaba el corpus no cuentan como RED de negocio. El corpus válido se generó antes de implementar: **76 fallos de fechas/contratos y 12 de ratings observados con stubs**.

**94 pruebas específicas pasan**, junto con Ruff/format y mypy estricto en 75 archivos. Los logs separan el corpus original, RED y GREEN. La cobertura medida ahora sirve como entrada de P24; no es aún aceptación final ni verificación de transporte público o proveedor real.

```sh

uv run pytest -q --cov=mealie_mcp_server --cov-branch --cov-report=json:artifacts/P19-coverage.json --cov-report=term-missing
```
