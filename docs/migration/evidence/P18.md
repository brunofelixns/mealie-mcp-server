# P18: imágenes, descarga fijada y multipart

Fecha: 2026-10-28. Se implementan set_recipe_image, set_recipe_image_from_file y set_recipe_image_from_url. **12 casos del MCP original** capturan cargas PNG/JPEG/WebP/GIF, data URI y jpeg alias, borrado con JSON y con 204, base64 inválido/vacío, extensión incompatible, URL delegada a Mealie y rechazo de un file privado. Bytes, nombre de archivo, tipo de contenido y campo extension se comparan en multipart; solo se elimina la variabilidad del boundary.

El caso positivo del archivo por MCP Python usa una descarga inyectada y una carga multipart HTTP real contra el fake. **No es una captura positiva del MCP original descargando un archivo público.** La referencia original sí ejercitó los cuatro formatos, hints engañosos y sus wrappers en recipe-image-file.test.ts y set-recipe-image-from-file-tool.test.ts, dentro de los 1058 tests de P03. La verificación Python separa descarga, herramienta nativa, metadata y persistencia, sin introducir acceso a Internet ni cambiar el servidor original para fingir esa evidencia.

Los bytes son la autoridad: máximo 10 MiB y firmas PNG/JPEG/GIF/WebP; mime_type y file_name no eligen el formato. Se conservan base64 URL-safe, padding tolerado por Buffer, whitespace ECMAScript, data URI y error ante extensión incompatible. Null borra una vez; 204 produce null MCP válido según D07. La herramienta from_url envía la URL a Mealie, como el original; no descarga ese recurso desde el MCP.

El descargador de file solo permite http/https sin credenciales. Resuelve cada salto una vez, rechaza respuestas DNS vacías o mixtas con IP privada/especial y conecta únicamente con los literales validados. Conserva el blacklist IPv4 y el allowlist IPv6 global del original, incluidos mapped IPv4 privados. Cada redirección vuelve a validar/resolver; máximo tres. El plazo total de 30 segundos incluye DNS, saltos y lectura; no se reinicia entre respuestas. Se aplica el límite tanto al Content-Length declarado como a los bytes recibidos, cerrando la respuesta al abandonar por error, cancelación o exceso de tamaño. Los errores de transporte inesperados se redactan según D06 y no copian excepciones que puedan contener una URL firmada.

HTTPX2 2.16.0 no ofrece network_backend en su transporte público, comprobado sobre el paquete instalado. Se usa el [backend público de HTTPCore](https://www.encode.io/httpcore/network-backends/) y [HTTPCore 2](https://pypi.org/project/httpcore2/), con AnyIO recibiendo IP numérica: no hay segunda resolución del hostname. El hostname original sigue en Host, SNI y verificación de certificado. Se comprueba también el peer real antes de enviar HTTP; el pool no toma proxies de entorno ni transmite credenciales Mealie. Se prueban sockets reales con fallback de ::1 a 127.0.0.1, rechazo del peer por defecto antes de enviar bytes, estado 700, TLS con CA de prueba y SNI original, rechazo del certificado con el trust store por defecto y proxies de entorno ignorados. Solo esos fixtures de red instancian un checker de peer permisivo para poder usar loopback; la ruta de la aplicación conserva el checker restrictivo.

La interfaz del transporte devuelve un contexto DownloadResponse con status, headers y body: permite decidir redirecciones y cerrar cada stream antes del salto siguiente. Se concreta el plan, cuyo AsyncIterator[bytes] por sí solo no exponía el estado/Location necesario. El máximo de conexión por dirección es cinco segundos dentro del presupuesto total; una dirección inaccesible permite probar la siguiente dirección validada.

FastMCP añadió automáticamente _meta.fastmcp.tags=[]; un test nativo lo detectó en RED. ContractTool ahora usa el hook público to_mcp_tool y preserva la metadata curada original. Se verifica todo el catálogo registrado: openai/fileParams aparece solo en file. No se oculta esa diferencia en el comparador. La comparación del resto de metadata/catalogo completo corresponde a P20.
