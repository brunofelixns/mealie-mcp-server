# P17: instrucciones con guarda de lectura

Fecha: 2026-10-28. Se añaden update_recipe_instructions y update_recipe_instructions_batch. **16 casos MCP capturados del original** comprueban reemplazo, delta sobre los índices originales, no-op, vaciado, lectura obsoleta, referencias desconocidas/duplicadas, formas incompatibles, cambios vacíos, hueco ambiguo entre dos instrucciones, recuperación correcta y recuperación que responde 200 pero no restaura el contenido, slugs duplicados y error 404 en lote.

expectedUpdatedAt es un token opaco que se compara exactamente con la lectura nueva de la receta antes de escribir. Los índices y las anclas pertenecen a esa lectura original. Los ids de instrucciones no se aceptan como identidad y se eliminan de los payloads escritos y restaurados. No hay condición atómica en Mealie: **una edición concurrente entre el GET de validación y el PATCH todavía puede sobrescribirse**. Esta guarda no se presenta como compare-and-swap ni como una transacción.

Las referencias de ingredientes explícitas deben ser UUID válidos, únicos sin distinguir mayúsculas y presentes en la lectura actual; no se infieren vínculos. Los campos omitidos, referencias existentes aunque estén dangling, noteReferences y campos desconocidos se conservan en delta. Los nuevos enlaces se normalizan en minúsculas; para comparar contenido las referencias se ordenan con comparación ordinal. Texto/título/summary se preservan sin recortarlos, salvo la comprobación de texto no vacío. Null en título o summary significa cadena vacía persistida, como en el original. Un no-op compara contenido canónico e ignora ids efímeros, por lo que devuelve la lectura actual sin escribir.

Se verifica el contenido devuelto por el PATCH y también el contenido devuelto por el PATCH de rollback. Una restauración incompleta se informa con rollbackSucceeded=false aunque el HTTP fuese 200. El lote conserva los resultados en orden de entrada, cinco recetas simultáneas y aislamiento de errores por receta; devuelve stale=true ante un token obsoleto. apiRequestCount cuenta aquí los intentos GET/PATCH, incluso fallidos, como hace el escritor original de instrucciones; no se uniforma con el contador histórico distinto de ingredientes.

La escritura emitida reutiliza la finalización protegida y acotada de P16. Las pruebas de este escritor cancelan durante lectura, envío y rollback: antes de escribir no hay efecto; después del envío terminan verificación y recuperación. Esta evidencia es local con transporte HTTP simulado; la desconexión de un cliente MCP por HTTP real corresponde a P22. No ofrece recuperación durable tras matar el proceso.

La función interna recibe changes con expectedUpdatedAt incluido, como la entrada del servicio original y de cada elemento del lote. Se concreta así la interfaz del plan; el argumento MCP expectedUpdatedAt conserva nombre, obligatoriedad, tipo y semántica.
