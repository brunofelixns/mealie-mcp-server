# P15: búsqueda y colas de auditoría

Fecha: 2026-10-28. La fase añade cuatro herramientas de lectura y sus modelos explícitos. La referencia conserva **35 casos MCP capturados del commit original**: clasificación por los cinco estados de taxonomía, parsing por los tres estados, filtros de enriquecimiento que reemplazan los defaults, combinación any/all, cursores inválidos, página vacía, límite y reanudación. La búsqueda cubre sugerencias, AND de foods, fallback de texto, plural, ambigüedad, duplicados sensibles a mayúsculas, límite truncado/capado y exclusiones por taxonomía.

Los tokens v1 se comparan byte a byte con valores generados por Node, incluidos caracteres Unicode. Se conserva la ordenación por createdAt/id con comparación UTF-16, la recarga de la página del cursor y el salto de posiciones ya procesadas. El cursor apunta al último elemento procesado, aunque existan detalles prefetched. Este mecanismo conserva el contrato original de paginación por páginas; **no proporciona un snapshot transaccional ni garantiza ausencia de saltos ante borrados concurrentes que desplacen páginas**.

El escaneo de auditoría obtiene lotes de 20 detalles con cuatro lecturas simultáneas y un presupuesto suave de 20 segundos; puede devolver cero coincidencias con hasMore=true y un cursor válido. Clasificación prefiltra con el resumen y solo pide los detalles seleccionados. Un detalle inválido o un error de lectura se reporta como dato individual; los errores de proveedor mantienen la política D06. Se verifican propagación de cancelación y ausencia de escrituras. Las auditorías cuentan forma y referencias almacenadas: las secciones puras no son ingredientes sin parsear; una cantidad positiva sin unidad y con food es partial, incluida una cantidad legítima de huevos. No hay interpretación lingüística.

La implementación utiliza un reloj monotónico para el presupuesto interno, inyectable en pruebas. El presupuesto conserva el carácter suave del original: no aborta a mitad de un lote ni reemplaza los timeouts REST. No modifica fechas de negocio ni campos de salida. El adaptador REST ofrece get_recipe_value para que la auditoría pueda distinguir una respuesta JSON inválida como receta de un error de transporte; get_recipe conserva su guardia de objeto para los consumidores anteriores.

RED observado: 31 fallos y 3 pases en las pruebas iniciales del escaneo/auditoría; 39 fallos MCP antes de registrar las cuatro herramientas. Tres casos adicionales detectaron que json.loads aceptaba NaN/Infinity dentro del cursor, a diferencia de JSON.parse; ahora se rechazan. El mock de JSON null se corrigió para enviar bytes de null, ya que httpx.Response(json=None) omite el cuerpo. Un test de error se ajustó al prefijo “Unable to retrieve foods” existente y confirmado en la fuente original.

Las herramientas de esta familia se registran en tools/recipe_queues.py para mantener los adaptadores de lectura separados de los escritores de recipes.py. Se actualizan plan y registro de archivos. No se introduce una API genérica de endpoints ni un catálogo de herramientas sin implementar.

Comandos dentro del Dev Container:

```sh
uv run python -m scripts.capture_cases recipe_queues
uv run pytest tests/unit/test_recipe_discovery.py tests/unit/test_recipe_scan.py tests/unit/test_recipe_audit.py tests/contracts/test_recipe_queues.py -q
uv run ruff format --check .
uv run ruff check .
uv run mypy src/mealie_mcp_server
uv run pytest -q
```
