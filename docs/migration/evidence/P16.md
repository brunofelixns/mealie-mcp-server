# P16: escrituras verificadas de ingredientes

Fecha: 2026-10-28. Se portan update_recipe_ingredients y update_recipe_ingredients_batch con reemplazo completo o delta por referenceId. **18 casos MCP capturados del original** cubren ambas herramientas, vaciado, campos null/cero, secciones, errores locales sin escritura, delta con anclaje, identidad de subrecetas, alias canónicos, verificación con rollback, slugs duplicados y fallo parcial de lote. El original queda separado de la expectativa Python D06 del error 404.

El delta conserva orden, campos desconocidos y filas no modificadas. Las inserciones que comparten ancla mantienen su orden de entrada. Se rechazan referencias inexistentes o ambiguas, operaciones duplicadas, actualizar y quitar una misma fila, anclas eliminadas y conflictos entre las formas de edición. No se crean ni buscan foods/units. El caso correcto cuesta un GET y un PATCH, más un GET por cada subreceta distinta; la subreceta se verifica antes de escribir y se rechaza la autorreferencia.

**Aclaración del criterio del plan:** la fuente original exige pares id/nombre antes de escribir, pero comprueba su correspondencia canónica en la respuesta del PATCH, usando nombre, plural, abreviaturas de unidades y alias almacenados. No hace una consulta adicional por food/unit. Se concreta el nombre de la prueba del plan para distinguir el par incompleto (rechazo antes de GET) del id/nombre incompatible (verificación y rollback después del PATCH). Añadir consultas preventivas habría alterado el contrato y coste original.

La verificación solo comprueba cardinalidad y asociaciones solicitadas; no exige que display u otros campos normalizados por Mealie vuelvan idénticos. En reemplazo, el rollback conserva el referenceId solicitado por posición cuando existe; en delta restaura la colección previa sin copiar identificadores por posición. Un rollback correcto sigue siendo un error de la operación inicial. El lote informa rollbackSucceeded y, si falla la restauración, rollbackError; no revierte recetas hermanas. Se conserva también el contador apiRequestCount del original: suma lecturas/escrituras completadas con éxito y el intento de rollback, pero no suma un GET/PATCH inicial que lanza un error. Por eso no es un contador fiable de todos los intentos HTTP; el caso parcial verifica el valor original 2 aunque el fake registre tres peticiones.

La adaptación de cancelación deja que una escritura ya emitida termine su verificación/recuperación dentro de un plazo de limpieza de **35 segundos desde la cancelación**. Usa shield de asyncio y un ámbito protegido de AnyIO para la cancelación por nivel de FastMCP. No reenvía una escritura ni restaura a ciegas ante timeout de envío: al agotar la limpieza cancela la petición y registra que el resultado puede ser desconocido. La cancelación durante la lectura previa no escribe. Pruebas con eventos, sin esperas temporales largas, cubren lectura, envío, rollback, AnyIO y agotamiento del plazo; no quedan peticiones activas. No garantiza recuperación tras matar el proceso/contenedor y el intervalo GET/PATCH no es una transacción ni detecta una edición concurrente.

AnyIO 4.15.1 ya estaba en el lock transitivo; se declara ahora dependencia directa y uv sync --frozen lo verifica sin cambiar paquetes. Pytest usa --import-mode=importlib: las dos pruebas prescritas por el plan tienen el mismo nombre en unit y contracts, y el modo anterior producía un error de colección. Esa incidencia de infraestructura se separa del RED de negocio: 20 contratos fallidos y 10 pruebas unitarias fallidas antes de la implementación. Tras implementar, **47 pruebas específicas pasan**; Ruff/format y mypy estricto en 66 archivos fuente pasan.

Comandos Dev Container:

```sh
uv run python -m scripts.capture_cases recipe_ingredients
uv run pytest tests/unit/test_recipe_ingredients.py tests/contracts/test_recipe_ingredients.py -q
uv sync --frozen
uv run ruff format --check .
uv run ruff check .
uv run mypy src/mealie_mcp_server
uv run pytest -q
```

Resultado final: **568 pruebas Python pasan en 109,12 s; 71/78 herramientas registradas**. Logs: artifacts/P16-reference.log, P16-contract-red.log, P16-unit-red.log, P16-first-green.log, P16-focused.log y P16-final.log. Las pruebas usan Mealie sintético; la desconexión mediante HTTP real queda para P22.
